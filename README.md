# E-Bike Ready OC

A mobile-first React + TypeScript web app that helps riders and families in Orange County, California understand e-bike classification, rider rules, local city rules and stopping distance.

- **Public app URL:** https://ebike-ready-oc.lovable.app/
- **Sources page:** https://ebike-ready-oc.lovable.app/sources

This app provides educational information only. It is not legal advice.

---

## Community problem

Many vehicles are marketed as "e-bikes," but not all of them meet California's
legal definition of an electric bicycle. Families and teenage riders often have
no simple way to answer two practical questions:

1. Does this vehicle actually meet California's e-bike definition (operable
   pedals, motor power, throttle behavior, assisted speed, speedometer)?
2. Can *this* rider, on *this* vehicle, legally ride in *this* place?

That gap creates real risk:

- **Overpowered vehicles.** A vehicle that exceeds the statewide motor-power or
  assisted-speed limits is not an e-bike, and the rider may be operating a
  different category of vehicle without knowing it.
- **Age restrictions.** California sets a minimum riding age for Class 3
  e-bikes, so a vehicle that is legal for one family member may not be legal for
  another.
- **Helmet rules.** Helmet requirements depend on the rider's age and, for
  Class 3, on the vehicle class as well.
- **Differing local ordinances.** Sidewalk, park, trail and local speed rules
  are set city by city. Two neighboring Orange County cities can treat the same
  ride differently, and posted signs can add restrictions the app cannot see.

E-Bike Ready OC brings the statewide vehicle definition, statewide rider rules
and verified city ordinances into one place, and is deliberately cautious when
it does not have enough verified information.

## Main features

- **Three-step vehicle Class Checker** (`/classify`) — a guided form grouped
  into Vehicle basics, Motor behavior and Legal verification. It returns
  Class 1, Class 2, Class 3, "Does Not Meet California E-Bike Definition" or
  "Needs Verification", with an explanation and the official citations behind
  the result.
- **Personalized Ride Check** (`/rules`) — combines rider age, e-bike class,
  helmet status, city and planned riding location (street, bike lane, sidewalk,
  park/trail, school campus) into a single verdict: "Likely permitted",
  "Verify before riding" or "Do not ride", plus a three-row logic trace
  (age/class, helmet, location) showing which sources produced each row.
- **Stopping-Distance Simulator** (`/stopping`) — an educational physics model
  that estimates reaction distance, braking distance and total stopping
  distance from speed, reaction time and road surface, with a speed comparison.
- **Decision Scenarios** (`/scenarios`) — a six-scenario learning activity with
  progress tracking and scoring that restates rules already verified elsewhere
  in the app. One scenario is generated by the Ride Check evaluator itself.
- **Sources & Methodology page** (`/sources`) — every statewide and city source
  the app uses, what each source is used for, how the app reaches a result, and
  the app's coverage limits.
- **Conservative "Verify before riding" result** — when a combination is not
  covered by verified data, or depends on on-site context such as a business
  district or a posted sign, the app returns an amber "Verify before riding"
  result. Amber means *this app does not have enough verified information* —
  not that riding is allowed.

## Rules-engine architecture

All legal facts live in typed data modules. UI components never hardcode a rule;
they call a pure function that reads that shared data. Everything runs
client-side — there is no account, database or external API.

**Layers**

1. **Typed shared rules data** — `src/data/californiaRules.ts` (statewide
   thresholds, notes and citations), `src/data/riderRules.ts` (statewide age and
   helmet rules and their sources), `src/data/cityRules.ts` (verified Orange
   County city records for Anaheim, Cypress, Garden Grove, Los Alamitos and
   Stanton, each with its own official sources), `src/data/rideLocations.ts`
   (the selectable riding locations) and `src/data/sourceRegistry.ts` (display
   metadata for the Sources page, derived from the two sets above — it adds no
   new rules and claims no new coverage).
2. **Vehicle classifier** — `src/lib/classifyVehicle.ts` takes one complete
   `VehicleInput` and returns a classification result with status, explanation,
   warnings and citations. The three-step form (`src/lib/classifierSteps.ts`) is
   presentation only and does not change the outcome.
3. **Statewide rider rules** — `src/lib/getStatewideRiderRules.ts` returns the
   age and helmet outcome for a rider age and class. A city selection never
   changes this statewide result.
4. **City rules** — `src/lib/getLocalCityRules.ts` returns the verified local
   record for a selected city, and `src/lib/getCoverageNote.ts` explains what
   the app does and does not cover for that selection.
5. **Ride Check evaluator** — `src/lib/evaluateRideDecision.ts` composes the
   statewide rider rules and the city record into one verdict, with a fixed
   precedence: hard statewide prohibitions and explicit local prohibitions
   produce red, unresolved or context-dependent situations produce amber, and
   only a fully resolved, non-prohibited combination produces green. It returns
   the exact source objects from the shared data — it never invents a citation.
6. **Data-generated scenarios** — `src/data/scenarios.ts` holds the scenario
   set, and `src/data/losAlamitosScenario.ts` builds its scenario by calling
   `evaluateRideDecision()` — **the same evaluator Ride Check uses** — so a
   scenario answer cannot drift away from the app's rules. Scoring lives in
   `src/lib/scenarioScoring.ts`.

**Handoffs between modules:** `src/lib/classHandoff.ts` carries a classifier
result into Ride Check (`/rules?class=…`), and `src/lib/stoppingHandoff.ts`
carries a class into the simulator as a starting speed
(`/stopping?speed=…&from=…`).

**File structure overview**

## Stopping-distance formulas

All of the math lives in `src/lib/stoppingDistance.ts` as pure functions.
Speeds are entered in mph, converted to m/s, computed in meters and displayed in
feet.

**Constants (exact values from the source)**

| Constant | Value | Unit |
| --- | --- | --- |
| `MPH_TO_METERS_PER_SECOND` | 0.44704 | m/s per mph |
| `METERS_TO_FEET` | 3.28084 | ft per m |
| `GRAVITY_MPS2` | 9.80665 | m/s² |

**Road-condition friction coefficients**

| Condition | Id | Friction (µ) |
| --- | --- | --- |
| Dry pavement | `dry` | 0.7 |
| Wet pavement | `wet` | 0.4 |
| Loose gravel | `gravel` | 0.3 |

**Input ranges used by the simulator**

- Speed: 5–45 mph, step 1, default 20 mph
- Reaction time: 0.5–2.5 s, step 0.1, default 1.5 s
- Comparison speeds: 20, 28 and 40 mph

**Formulas**

```
v (m/s)           = speed_mph × 0.44704
reaction distance = v × reaction_time_seconds          (meters)
braking distance  = v² ÷ (2 × µ × 9.80665)             (meters)
total distance    = reaction distance + braking distance
feet              = meters × 3.28084
```

Full precision is kept in the calculation; rounding to whole feet happens only
at display time (`roundFeet`).

**Assumptions and limitations**

- The model assumes level ground — no uphill or downhill slope.
- Actual stopping distance also depends on brake condition, tires, rider skill,
  bicycle and rider weight, slope and weather.
- The 40 mph comparison is shown for context only: a vehicle providing motor
  assistance at that speed does not fit California's Class 1, 2 or 3 e-bike
  limits.
- This is a simplified educational estimate, not a guaranteed stopping distance,
  and it is not a legal rule — it never changes any classification or Ride Check
  result.

## Testing

Current verified state: **208 passing automated tests across 14 test files**,
with clean TypeScript type checking (no type errors).

Important edge cases covered by the existing test files:

- `src/lib/classifyVehicle.test.ts` — the five classification outcomes,
  including the Class 3 speedometer requirement (No → not an e-bike, Unsure →
  Needs Verification), the manufacturer-advertised-modification cases, and the
  no-operable-pedals result.
- `src/components/classifier/ClassifierForm.test.tsx` — step visibility,
  Next/Back navigation, answer persistence across steps, submit only on Step 3,
  Edit answers / Start over, and the `/rules?class=…` handoff.
- `src/lib/evaluateRideDecision.test.ts` — the full precedence table: under-16
  on Class 3 is red; a legally required helmet answered "No" is red; an
  unverified class or an unsure helmet is amber; statewide-only city leaves the
  location unresolved; explicit local prohibitions (Anaheim park, Anaheim
  Class 3 sidewalk) are red; school campuses and conditional park rules stay
  amber; a red rule always overrides amber uncertainty; and the evaluator only
  ever returns citations that already exist in the verified source sets.
- `src/lib/getStatewideRiderRules.test.ts` and
  `src/components/rules/RiderRules.test.tsx` — statewide age and helmet
  outcomes, strict age validation (whole numbers 1–120), and clearing results
  when the form is edited.
- `src/lib/getLocalCityRules.test.ts` and `src/lib/getCoverageNote.test.ts` —
  city lookups and the coverage wording for covered vs. statewide-only
  selections.
- `src/lib/losAlamitos.test.ts` — the Los Alamitos scenario is produced by the
  same Ride Check evaluator.
- `src/lib/scenarioScoring.test.ts` — scoring, one credit per scenario, progress
  labels and completion.
- `src/lib/stoppingDistance.test.ts` — verification cases at 20, 28 and 40 mph
  on dry pavement, total = reaction + braking, and lower friction producing a
  longer stop.
- `src/lib/classHandoff.test.ts` and `src/lib/stoppingHandoff.test.ts` — the
  module-to-module handoffs.
- `src/routes/routing.test.tsx` and `src/routes/sources.test.tsx` — routes still
  resolve, and the Sources page renders every statewide source and all five
  verified cities.

## Official sources

Legal information in this app comes from official California Vehicle Code
sections, California Highway Patrol and California DMV material, and official
city-government ordinance and municipal-code sources for the five verified
Orange County cities (Anaheim, Cypress, Garden Grove, Los Alamitos and Stanton).

Every citation used by the app, what it is used for, and a link to the official
text are listed on the Sources & Methodology page:
https://ebike-ready-oc.lovable.app/sources

Legal information was last reviewed in **July 2026**. Laws, local codes and
posted signs can change, so check the current official source before you ride.
If the wording in this app differs from the official source, the official source
controls. This is educational information, not legal advice.

## Run locally

You need Node.js and npm.

```sh
# 1. Install dependencies
npm install

# 2. Start the development server
npm run dev

# 3. Run the automated tests (208 tests)
npx vitest run

# 4. Type-check the project
npx tsc --noEmit

# Other scripts defined in package.json
npm run build       # production build
npm run build:dev   # development-mode build
npm run preview     # preview a production build
npm run lint        # ESLint
npm run format      # Prettier
```

Note: `dev`, `build`, `build:dev`, `preview`, `lint` and `format` are the scripts
defined in `package.json`. Vitest and TypeScript are installed as dev
dependencies but have no dedicated script, so they are run directly with `npx`.
